HOW THE NON-PURE ITEMS ARE FROZEN, AND WHAT PLAYWRIGHT ALREADY COVERS
URL state
  Node freeze: url.state. 9 configurations x (serialize + round trip) and 19 crafted hashes
  (malformed base64, out-of-range values, gain above default, continuous repeat, binaural in link,
  array extra, unknown pattern keys, invalid sequence, legacy sweepUp-in-sweep, custom range with
  'rm' precedence, invalid octave span, bad a4, unknown mode, foreign continuous keys), each at a
  provisional rate (null) and at 48 kHz. The state, notices and pendingHashConfig are captured.
  Existing Playwright: smoke "URL hash restores configuration" (fm/1500/modFreq 7), "URL never
  restores continuous permission or playback", "malformed URL handled with a visible notice";
  spec §43 "hash sweep.repeat continuous restores once", "hash never restores continuous
  permission", "no AudioContext created when loading from a hash".
  Gaps: the browser does not test the pendingHashConfig re-apply after the first gesture at
  48 kHz (above-provisional link). Add: open #f=23000&rm=advanced, press, assert frequency =
  22800. The browser does not test the a4 / custom-range links, and copyConfigLink's clipboard
  fallback modal is untested.
Storage schema / migration
  Node freeze: storage. presetRecord over 6 cfg shapes, migratePreset over 14 inputs (v0, v1,
  v99, bad names/ids/created), loadCustomPresets over 7 stored payloads, the save/delete/persist
  flow, blocked (throwing) storage, loadHistory over 5 payloads, addHistory dedupe + 50 cap,
  safety-notice session key, runtime flags never serialized.
  Existing Playwright: smoke "custom preset saved with versioned schema", "loads and deletes",
  "session history recorded", "storage failure handled"; spec §41 (v0 migrated, invalid and v99

  Gaps: the theme key write (setTheme needs the DOM) is untested. Migrated v0 presets get a new
  id and created stamp on EVERY load because migration is not persisted (frozen as-is; likely a
  defect). There is no test for the 200-preset cap.

AudioEngine stop semantics
  Node freeze: engine.stop runs 37 scenarios on a recording mock AudioContext (every node, every
  connection, every AudioParam event, every start/stop time). Covered: the output chain and trim,
  hold/release while running, release mid-attack and mid-release WITHOUT cancelAndHoldAtTime
  (the Firefox _holdEnv path, value interpolation checked), natural end, release after the
  programmed end (no-op), release on a suspended context (immediate free), 20 play/stop cycles,
  play-while-playing overlap, the safety limit, a limit shorter than the attack, continuous
  unlimited, trigger durations, the topology of every plan type (dual with and without
  StereoPanner), updateLive per type incl. rejections, instantaneousFrequency and master gain
  clamping. Invariants per scenario: no gain hard-set to 0, no non-finite automation times, no
  oscillator scheduled at or above the safe maximum, zero active nodes and every voice node
  disconnected after the end. app.transport (7) drives the component + engine: trigger, programmed
  pattern, latch gate, key hold/repeat/release, Escape, invalid config error, reset while playing.
  Existing Playwright (real AudioContext): smoke "release stops and frees every node", "40 rapid
  play/stop cycles leave zero nodes", "no oscillator accumulation", "finite tone ends on its own",

  0.08", "spectrum peak at 440 Hz", and per-browser release-level checks ("stop … never raises
  the level", "starts from the held level", "frees every node").
  Gaps: the mock freezes the SCHEDULE, not the rendered audio. Keep the Playwright level checks
  and run them on Firefox (the _holdEnv fallback) as well as Chromium. Rendered-click detection

  threshold), which is feasible in the browser with no new dependency. Mic start/stop has only a
  start/stop track check.

     pure-API vectors IN PAGE against dist/index.html and compare with golden.json. This guards
     bundler/minifier/scope drift (hazard K1) that the Node harness cannot see.
  2. Keep the smoke/spec engine checks unchanged in substance; retarget them to dist/ and to the
     new markup.
  3. Add explicit browser checks for the gaps above (pendingHashConfig re-apply, Firefox release
     path, OfflineAudioContext click check, theme storage).

V1 quirks frozen as-is (decide deliberately in V2; do not "fix" silently)
  - buildPlan: an invalid durationMs ('x') becomes the MINIMUM (20 ms sweep pass), not the default.
  - buildPlan: frequency NaN silently falls back to 440 Hz, while 0 or negative is an error.
  - formatFrequency(0.004) -> "0 Hz"; formatFrequency(-1) -> "-1 Hz".
  - applyConfig clamps a frequency above safeMax with 0 issues (loadPreset blocks disabled presets
    first, but links do not).
  - Migrated v0 presets: unstable id/created across reloads (not persisted after migration).
  - Round trip is lossy by design for gain > 0.08 (capped) and repeat 'continuous' (-> 'once').
