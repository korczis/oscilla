# A dist-changing pull request conflicts on dist/index.html after every merge; take either side and rebuild dist once after the last merge

Observed as repetition about dist/index.html in episode s-20261017232612-d03c.

- `issue:179`
- `commit:62cccb363c9b71e22c2df311a6222012761df04c`

# Evidence

Every pull request that changes `src/` also commits the rebuilt `dist/index.html` (ADR 0011).
After any one of them merges, every other one conflicts on `dist/index.html`, and resolving it
by hand is meaningless: the file is a deterministic build output. Take either side of that one
file, finish the merges, then run `npm run build` once and commit the rebuild; `build:check`
proves the committed file equals a clean rebuild. Every other conflict is resolved by hand,
and no conflict marker is committed (`project.no-conflict-markers`). Batched, N ready pull
requests cost one rebuild and one CI round instead of N.
