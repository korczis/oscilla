# majordomus finish --note takes a FILE whose sections are policy handover.required_sections (# Objective, # Current State, # Next Action); a missing section is refused

Observed as friction about command:finish in episode s-20261017232612-d03c.

# Evidence

- `file:.ai/repo/policy.yaml`
- `file:.ai/repo/workflows/task-lifecycle.md`

# Evidence

`majordomus finish --note <file>` takes the path of a Markdown file, not the note's text. For
`--outcome completed` the file must carry every section the policy's
`handover.required_sections` lists, which in `.ai/repo/policy.yaml` is `Objective`,
`Current State` and `Next Action` as `# ` headings; `partial` and `blocked` need only
`# Next Action`. Without `--note`, finish uses the newest handover recorded for the task, and
with neither it refuses (`no --note file and no handover for this task`). The doctrine is
`majordomus.note-integrity`; the reader is `mj_validate_note` in the distribution's
`lib/finish.sh`.

How it was paid for: on 2026-10-03, under Majordomus 0.12.0, a note piped through
`/dev/stdin` left a task completed with an empty note and no `task.finished` line. Releases
since stage the note once before judging it (0.29.0 reads a pipe correctly), but a real file
in the scratchpad is still the form that is unambiguous on every version. The task lifecycle
workflow shows `finish` without `--note`, so a worker following it alone meets the refusal.

- file `.ai/repo/policy.yaml`: `handover.required_sections: [Objective, Current State, Next Action]`
- file `.ai/repo/workflows/task-lifecycle.md`: the finish line that omits `--note`
- `majordomus finish --help` (0.29.0): `--note  a completion note (required sections as a handover)`
