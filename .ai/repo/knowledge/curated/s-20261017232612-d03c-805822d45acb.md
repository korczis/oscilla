# With a newer Majordomus installed, every commit on a branch whose .ai layer is older fails the pre-commit doctor; branch from the migrated head

Observed as friction about command:doctor in episode s-20261017232612-d03c.

# Evidence

- `file:.ai/repo/adrs/0056-majordomus-pin-moves-with-the-layer.md`
- `issue:178`
- `commit:239954446f046da914f7511f9d4546d2a0508802`

# Evidence

The git hooks and `npm run verify` run whichever `majordomus` is on PATH, and the pre-commit
hook runs `majordomus doctor`. When the launcher already runs a newer release than the one the
branch's `.ai/` layer was migrated for, doctor reports failures on that layer (missing required
policy keys, vendored rules whose validators the new release ships) and every commit on the
branch is refused. In #178's case the launcher already ran 0.29.0 while the layer was 0.23, so
every pre-commit doctor on a 0.23 layer failed until the migration landed.

What to do: start the branch from the head that carries the migrated layer (the train or the
migration branch), or merge that head in before the first commit. Never work around the hook
with `--no-verify`.
