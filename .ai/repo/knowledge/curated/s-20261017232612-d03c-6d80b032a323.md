# The Pages deployment of main carries the last release's version label while its artifact differs from the released one, because releases lag main

Observed as drift about .github/workflows/pages.yml in episode s-20261017232612-d03c.

# Evidence

- `file:.ai/repo/adrs/0028-provenance-without-a-fixed-point.md`
- `file:scripts/release-cadence.mjs`
- `file:.ai/repo/rules/project/deploy-often.v1.md`
- `commit:964e25d7e009eaa290540cdbf24edee6e07cb66c`

# Evidence

The product version lives only in `package.json`, and it changes only in a
`chore(release): vX.Y.Z` commit. The Pages workflow deploys every push to main and stamps the
build-metadata region with the deployed commit (ADR 0028). So between releases the public page
says the last release's version while its source digest, commit and artifact differ from the
released ones: a "v3.10.3" label is not proof of the v3.10.3 artifact. Identify a deployment by
`commit` and `artifactSha256` in the `oscilla-build` region, never by `version`.

Measured on 2026-10-18: https://korczis.github.io/oscilla/ served `version` 3.10.3 with
`commit` 964e25d7e009eaa290540cdbf24edee6e07cb66c and `sourceDigest` cc7af440...; the tag
v3.10.3 (commit e4772ee7ef973cf4d733a5ff4a9cd931b48c7285) has `sourceDigest` a9bb3969...; 155
commits separate them. `node scripts/release-cadence.mjs --report` reported the release
OVERDUE: 120 releasable commits since v3.10.3, the oldest 269 h old against the 24 h limit.
