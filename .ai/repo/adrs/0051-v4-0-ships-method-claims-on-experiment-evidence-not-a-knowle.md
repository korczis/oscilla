# 51. v4.0 ships method claims on experiment evidence, not a knowledge explorer

## Context

The v4 completion ledger lists, under "What v4.0 still lacks entirely", item 6: "A knowledge
explorer fed by a build-time index of claims, features, rules, ADRs and releases". Its matrix
row reads MISSING / static About. Neither release decision in the ledger names it as a blocker.
The only tracked trace of a deferral is one sentence in ADR 0044: the owner's scope decision of
2026-10-05 "rejected a knowledge explorer or a workspace shell for now". The brief the ledger
cites is not in the repository.

The owner's steering for v4, word for word: "depth over breadth; fewer new nouns, more working
verbs; acoustic measurement is the wedge; the meta-layer must not grow for its own sake;
Majordomus must pay rent; the single file is not a religion".

The owner approved the direction recorded here on 2026-10-07. This record stays `proposed`;
accepting it is the owner's edit.

A saved record is called an experiment here. ADR 0044 and the claim id `run-evidence` keep the
names they were written with.

Four facts decide what an explorer could honestly show a user of an acoustic lab:

1. **"What changed in this release" cannot be told by the page being released.** A release
   record is written after publish, and its web artifact sha256 names the bytes of
   dist/index.html (.ai/repo/releases/README.md). GitHub release notes are generated by
   release:publish from the commits since the previous tag, after release:prepare has built and
   gated the dist. The build carries no clock and no git state (project.single-file-deliverable
   v2). The 13 existing records (v3.4.0 to v3.10.3) hold no change content at all. A link to the
   notes derived from BUILD.version would 404 between the merge of the release:prepare commit
   (Pages deploys main) and release:publish, which creates the tag.
2. **An index of ADRs, rules and features answers maintainers' questions, not a measurer's.** It
   would cost about 77 KB gzip for the ADRs alone, and every ADR on main has status proposed.
   The product would present undecided records as fact.
3. **An index read from docs/ or .ai/ would go stale silently.** Neither is a build input:
   the source digest covers src/, licenses/ and a fixed list of files
   (scripts/release-metadata.mjs). Docs-type commits deploy to Pages without a release. Text
   injected at build time from outside src/ is also outside the project.no-fake-science
   scanner, which reads src/index.html and the string literals of src/js.
4. **Claim prose was not checked against the code.** Claims are keyed by kebab ids, not by
   algorithm ids. Until this change the impulse-response note named
   oscilla.ir.farina-inverse.v1 as the test oracle, while ALGORITHMS.irFarina is
   oscilla.ir.farina-inverse.v3, v1 and v2 are retained, and the test runs the default.

What a user does need, at the point of doubt, is an answer to "why should I trust how this
stored number was computed?". An experiment's Evidence (ADR 0044) already prints each algorithm
id and version on the Analysis link. Algorithm ids are stable and versioned: a change that can
alter a stored number gets a new version (ADR 0024). Nothing maps an id to the claim and test
that verify it.

## Decision

1. **v4.0 ships no knowledge explorer** and no build-time index of claims, features, rules,
   ADRs or releases. Ledger item 6 is descoped as written. The About view stays hand-written and
   is kept current by tests/unit/about.test.mjs under project.about-names-current-release.
   "What changed" stays on GitHub Releases, reached from the About source and commit links.
   ADRs, rules, feature records and release records are not shipped to users.

2. **A saved experiment's Evidence gains one list, "Why trust the method?"**, placed between
   "What produced this value?" and "Can I repeat this?". For each role in the stored
   `algorithms` map it shows one state, in words, never as a score:
   - **claimed**: the id is a current default that a guaranteed claim covers. The list shows
     the claim sentence word for word and the claim's test path. On the production channel
     the path links to the source at BUILD.commit; elsewhere it is plain text.
   - **superseded**: the id is retained. The list names the current id and says the current
     claim does not cover this version.
   - **unclaimed**: the id is a current default with no published accuracy claim. The list
     says so.
   - **unknown**: the id is well formed but unknown to this build. The list says a different
     build wrote it.

   A fixed hint follows the list: the claims are about the method, tested on known inputs; they
   do not rate this experiment, its quality rating does; and no automated test proves how a
   physical speaker, room or microphone behaves.

3. **The mapping is strict.** An id is claimed only when the claim sentence is about that
   method's behaviour. A test oracle (farina-inverse) or an input to another claim's rule set
   (clip, discontinuity) is unclaimed. Initial mapping: transfer.v3 to transfer-function;
   ir.log-sweep.v3 to impulse-response; rta.v2 to rta-bands; confidence.v4 to
   measurement-quality; calibration.log-interp.v1 to calibration-profiles; aggregate.v1 to
   aggregate-primary-response. The other eight current defaults are unclaimed.

4. **The text lives under src/** in src/js/measurement/method-claims.js, a hand-written mirror.
   It is a source-digest input (so build:check covers it) and is inside the no-fake-science
   scanner's scope. A unit test requires:
   - each mirrored sentence and test path to equal docs/CLAIMS.yaml character for character;
   - the mirrored keys and the unclaimed list to be disjoint and together equal the current
     ALGORITHMS defaults exactly.

   Changing a mirrored claim sentence, or bumping a default algorithm version, therefore fails
   CI until a person re-maps it. If the scanner rejects a mirrored sentence, the claim wording is
   fixed; the scanner gains no exemption. Rows are bound with x-text only.

5. **Claim prose names only current or retained ids.** A check fails on any oscilla.*.vN token in
   a claim record that is not a current default, unless that line says it is retained
   (tests/unit/knowledge-integrity.test.mjs). This part ships with this record.

6. **No new claim id, view, record kind, CLAIMS.yaml field or build step.** The run-evidence
   claim gains one sentence covering the list. The evidence.js header says that this list comes
   from the running build, not from the stored record, so "nothing is inferred" still holds for
   the lineage and the checklist.

7. **Order of work.** This record, the ledger update and the check of point 5 change no byte
   of dist/index.html. The list of point 2 is built afterwards, in its own pull request, once
   findings (#149) and connected records (#151) have landed, because all three edit the same
   Evidence section.

8. **Reopen trigger.** A wider explorer is reconsidered only for a named user question about a
   stored experiment that the Evidence section cannot answer. Before it ships it must meet
   three preconditions:
   - the build reads every index source, so build:check and the source digest cover them;
   - the no-fake-science scanner covers every injected sentence;
   - every claim it shows is keyed to machine-checked algorithm ids.

   While project.single-file-deliverable v2 holds, a dist never shows its own release record or
   its own release notes.

## Alternatives rejected

- **The explorer as written (claims, features, rules, ADRs, releases).** It serves maintainers.
  Context points 2 and 3 apply: undecided ADRs would be presented as fact, the index would go
  stale silently, and the injected text would sit outside the scanner. It is the meta-layer
  growing for its own sake.
- **"What changed in this release" from release records or notes.** Context point 1: the page
  cannot carry its own record or notes, and a version-derived link 404s in the publish window.
- **Descope with zero product change.** Honest and free, but it leaves a user asking "why trust
  this number" with the About paragraph only. It also leaves the claims ledger paying no rent to
  a user, even though a small key (exact algorithm ids, checked by a test) makes a safe answer
  possible today.
- **A generator from a new `algorithms:` field in CLAIMS.yaml to a generated module.** This is
  more machinery: a schema field, a script, an npm script and a parser extraction into scripts/.
  A docs: edit to a claim would turn into a CI failure until someone regenerated the module. The
  hand-written mirror plus an equality test gives the same staleness guarantee.
- **Pairing farina-inverse.v3 with the impulse-response claim.** That sentence describes
  regularised spectral deconvolution, and Farina is only its test oracle. Showing it beside a
  Farina-derived IR would attribute a claim to a method it does not describe.
- **A new claim id for the list.** One sentence on the existing run-evidence claim covers it
  and adds no noun.
- **Adding docs/CLAIMS.yaml to the source digest.** Every edit to an unrelated note would change
  the digest and the dist, and parallel PRs would conflict on dist/.

## Consequences

- Ledger item 6 is annotated "descoped by ADR 0051 (proposed)", not deleted. Its matrix row
  reads DESCOPED, and "Method claims on evidence" is listed as an open v4.0 item with a matrix
  row that stays MISSING until the list lands. The ledger's release decisions are not edited:
  neither of them names the explorer as a blocker, and this record adds none. The list ships in
  a minor release or in 4.0.0-rc.1 (ADR 0047). The descoping counts only once the owner marks
  this ADR accepted.
- Users see that 8 of the 14 current methods carry no published accuracy claim. That list is
  the depth-over-breadth backlog for the measurement wedge.
- Deliberate friction: editing one of the six mirrored claim sentences means editing two files,
  and the src edit is a fix or feat commit that ships a release. Bumping a default algorithm
  version forces a decision on whether its claim still covers it.
- The list proves linkage, not truth. The shown sentence is the published claim and its test
  runs in CI; that test, not the list, is the proof.
- This record costs 0 bytes in dist/index.html. The list is estimated at 2-3.5 KB gzip, to be
  replaced by the measured delta in its pull request, against the 1,000,000 B budget.
- ADR 0044's "for now" sentence stays as history. The untracked Majordomus knowledge candidate
  that records the deferral is left to Majordomus and not hand-edited.
